# Archon Soulings Living Nexus — Continuation Contract

Status: CANONICAL CONTINUATION RULE for Living Nexus implementation, preview deployment, and future agent handoffs.

This file exists because the project has repeatedly drifted from the established Living Nexus vision while preserving only its mechanics. That is not acceptable. Future work must preserve both the tested architecture and the established living visual environment.

## Governing rule

**The Living Nexus is a living operating environment, not a conventional website, dashboard, card grid, fantasy landscape, or utilitarian prototype.**

A build passes only when BOTH of these remain true:

1. the tested Living Nexus architecture and interaction behavior are preserved; and
2. the established living auric visual/environmental authority is preserved.

A green functional test suite does not authorize a visual regression.

A visually impressive composition does not authorize breaking the tested architecture.

If either side regresses, the build is not a release candidate.

## Source-of-truth order for continuation work

For Living Nexus continuation and deployment work, use this order:

1. this continuation contract;
2. `wix/LIVING_NEXUS_PREVIEW_DEPLOYMENT.md`;
3. the current tested `hud/prototype/` architecture and integration behavior;
4. the established Archon Soulings Living Nexus visual acceptance references from the project conversation/history.

Do not treat whichever file was edited most recently as permission to reinterpret the vision.

Do not rebuild the system from scratch unless the owner explicitly requests a redesign.

- minimal persistent explanatory UI;

## Explicit non-regression rules

Do NOT replace the accepted Living Nexus visual language with:

- generic dashboard cards;
- admin/control-panel styling;
- ordinary app-shell sidebars as the dominant composition;
- large rectangular explanation blocks;
- a conventional landing-page hero followed by sections;
- a flat menu of destinations;
- stock sci-fi HUD styling disconnected from the living auric field;
- decorative pseudo-Aureglossa glyphs;
- fantasy-landscape artwork used as the interface itself;
- a simplified prototype merely because it is easier to deploy.

Utility controls may exist, but they must remain subordinate to the living-field composition.

If deployment constraints require a temporary fallback, label it as a fallback and do not call it the Living Nexus release candidate.
