1. **Aura Dynamics — The Living Field** (crown).

4. **Workshops — The Convergence** (lower-left).

These six are a spatial/semantic architecture, not six independent UI discs. The environment includes membranes of continuous luminous matter, intricate refracted light, responsive filaments, dark negative space, a relational Living Thread, ambient Stillness, Guide Me, and a governing inscription.

**Approved product behavior:** functional portals to the six worlds; genuine dimensional crossing and return; Living Thread and Field Journal/Passport; Guide Me; relational Search and Provenance; privacy-conscious Soul consent; Stillness and reduced motion; owner-opt-in Atmosphere with immediate Silence; authentic Save and Dissolve actions. **Stillness is a visual benchmark:** at rest, the rendered, interactive six-world composition must retain the richness and relational light of the approved image. A flat six-circle menu with impressive motion fails this benchmark.

## 5. Rule for concurrent chats and agents

1. **Start each work session by reading this gateway and current canonical files**, then fetch the *live* branch SHA and open PR/CI status.
2. Declare a **workstream and exclusive file scope** before changes. Do not have two chats rewrite the same renderer or governance file without reconciling heads; use separate experiment paths for competing prototypes.
3. Preserve the last tested architecture. Do not transform experiments into the default/public app without a reviewed migration plus functional regression and owner visual approval.
4. Report independently: \`IMPLEMENTED\`, \`TESTED\`, \`VISUALLY ACCEPTED\`, \`PREVIEW DEPLOYED\`, \`PRODUCTION DEPLOYED\`; record \`PASS / FAIL / NOT VERIFIED / BLOCKED\` for each. Never collapse these into “done.”
5. End each meaningful work session with a handoff entry: chat identifier/link if owner supplied, scoped files, starting SHA, ending SHA, CI link, screenshot/video evidence, owner acceptance state, changed APIs/storage, unresolved blockers, and next **single** priority.
6. **No canonical takeover:** do not silently rewrite reference hierarchy, project naming, existing commit history or visual authority. Conflicts must be recorded as \`CONFLICT — OWNER DECISION REQUIRED\` until explicitly resolved.
7. **Private/public isolation:** communicate only implementation-neutral motion observations across all private/public product boundaries. Private details stay in private project files and chats.
